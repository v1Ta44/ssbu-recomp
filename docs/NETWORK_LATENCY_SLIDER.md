## 1. 已经定位清楚的参数

| 项目 | 本次结果 |
|---|---|
| 目标游戏版本 | 本项目的 13.0.4 dump |
| 计算函数入口 | `0x71016ccae0` |
| 对应原滑块内部插入位置 | `0x71016ccc58` |
| 参数位置 | 函数输入对象 `x0 + 65`，一个字节 |
| 原函数范围 | 400 字节 |
| 原函数 SHA-256 | `321ce8ab4a70fed64737950bdc8feac5b1eb258bfa39998b62db4fb3ebb98ecf` |
| 本机调用线索 | 初始化路径和周期性网络处理路径都能调用；详细生成代码留在忽略目录 |

Online Deluxe 当前源码写死的 `0x16ccab8` **不能直接用于此 13.0.4 dump**。本次利用已有公开滑块的定位线索，在用户本地 dump 中找到了对应位置，并检查了包含它的完整函数。旧地址位于另一处网络处理函数中，直接移植会有误写风险。

原函数在计算后更新对象的第 65 字节，并把该值限制到不大于 25；部分分支直接保留已有值。可以在函数入口保存对象地址，执行原函数，在返回后覆盖这个字节，得到与其内部返回位置覆盖相同的目标字段，同时保留原函数返回的寄存器、标志和栈。

插件没有复制游戏计算公式，也没有重编译、重写或替换游戏 DLL。游戏计算体只会在自动测试时从用户已有的生成文件中提取到本机 `build/` 下，不进入提交。

## 2. 实验怎样工作

`mods/latency_slider/latency_slider.cpp` 是使用项目现有 HookApi 加载的原生 DLL。

- 启动默认 Auto；允许选择 0～25 帧。
- 原函数总是先执行；Auto 不写游戏状态。
- 手动覆盖要求：房间已加入、LDN 为已创建主机会话或已连接客机、节点数为 2～8。
- 函数执行前后都读取一份小型 LDN 状态，房间代次、LDN 代次或角色发生变化时跳过这次覆盖。
- 在加载时检查真实映射的 ARM 函数 SHA-256；不匹配就不安装 hook。
- 旧宿主没有 LDN 状态查询接口时也不安装 hook，避免在不清楚模式时修改输入参数。
- 原函数结果超出支持范围、目标内存不可访问或不可写时保留结果。
- 只在本次函数返回时使用保存的对象地址，界面不会持有旧对象并定时写入。
- 所有选择与函数调用都记入独立 CSV，不修改或添加玩家之间的网络消息。

这改变的是本机游戏的输入等待参数。它不会降低网络传播时间，不会自动替对手选同一帧数，也没有增加输入预测或历史重模拟。

### Auto 的准确含义

选择 Auto 表示**停止后续手动覆盖**。本次专门验证了原函数“保留旧值”的分支：如果它没有重新计算，该字节可能暂时保留上一手动值。因此界面显示“游戏给出的值”，而不是保证每次都是新算出的自动值。

需要干净的 Auto 对照时，先选 Auto，再退出并重新进入游戏的本地无线会话；最稳妥的基准是重新启动实验程序。界面选择在游戏下次调用目标函数时生效，不承诺比赛中立即变化。关闭选择窗口会把后续选择设回 Auto。

## 3. 对主项目的改动面

| 文件 | 用途 |
|---|---|
| `runtime/yuzu_net.h`、`runtime/yuzu_net.c` | 增加只读 `ssbu_net_ldn_snapshot()`，返回小型、复制的 LDN 上下文 |
| `mods/latency_slider/control.h` | 插件控制与观察结果接口 |
| `mods/latency_slider/latency_slider.cpp` | 函数包装、版本检查、会话条件、CSV、选择窗口 |
| `scripts/build_latency_slider.py` | 构建独立宿主与插件，校验原始输入未变 |
| `scripts/play_latency_slider.py` | 一次启动联机面板与实验，隔离存档、配置和日志 |
| `scripts/analyze_latency_slider.py` | 汇总调用、应用和跳过原因；不把参数记录冒充延迟测量 |
| `LatencySlider.bat` | 正常人工实验入口 |
| `LatencySliderReport.bat` | 汇总最近一次运行 |
| `tests/latency_slider_native.cpp`、`tests/test_latency_slider.py` | 实际生成计算函数与插件的对照、条件和界面测试 |
| `tests/yuzu_backend.c` | 在现有协议测试中验证新查询接口 |

新接口是附加导出，不改变原来的 `SsbuNetSnapshot` 布局、网络 ABI 版本或网络报文。查询时在原网络锁内复制状态，返回后不暴露后端内部内存。

构建器将整个运行时目录按相对路径放到独立目录，保留 `r1src/` 子目录，不把里面的包装文件覆盖到根目录。它只读取既有生成输入，并复制游戏 DLL 和已编译模块；不调用 lift、游戏编译或游戏 DLL 链接。常规宿主、游戏 DLL、ELF 构建前后的 SHA-256 必须一致。原模块加载器只支持相对于宿主的目录，因此模块也复制到独立宿主旁；没有用跨盘绝对路径冒充可用的模块目录。

与帧索引任务的集成边界：没有改动 `runtime/display.c`、`runtime/nvn_*`、重编译器、现有构建入口或帧索引补丁。后续只需合入本分支的小型网络查询接口和独立工具；是否把它与帧索引实验放在同一次运行中，留给分别验证后的集成步骤。

### 原计算函数与包装器

每轮执行 **2,125 个计算/条件用例**，其中 1,887 次满足条件并应用手动值。分别以普通模式和隐藏控制窗口模式执行，两轮均通过。

覆盖：

- Auto、0～25 帧、多个原设置分支、多个输入量级和原函数上限处理。
- 对原函数和包装器使用相同的内存与初始状态，对比完整 Ctx、栈、对象其他字节；手动模式只允许第 65 字节不同。
- 未加入房间、单人会话、不同 LDN 状态、无效节点数，以及查询接口失败。
- 计算期间房间代次、LDN 代次或角色变化。
- 不匹配的目标指纹不安装 hook；缺少新上下文接口不安装 hook。
- 非法配置与越界选择。
- 原函数复用旧值时，Auto 仅停止覆盖，不伪造自动重算。
- 隐藏窗口中的选择、恢复 Auto、关闭窗口行为。

## 8. 下拉框选择回跳修复（2026-10-18）

修复了鼠标选择帧数后仍显示 Auto 的问题。旧窗口在每个控件通知上都刷新已保存值，而原生下拉框可以在 `CBN_SELCHANGE` 前先发送 `CBN_SELENDOK`；该刷新会把待提交选择覆盖回 Auto。250 ms 定时刷新也不应在列表展开时重新设置选择。

现在处理选择变化和确认通知时保存值，其他展开、收起和焦点通知不重置下拉框；列表展开期间不做选择同步。测试新增“选 3 帧、先确认通知再选择通知、随后定时刷新和收起”的序列，已先复现旧实现失败，再验证修复通过。原有计算和会话条件用例继续通过。

已运行的游戏进程仍加载旧插件；退出后重新打开 `LatencySlider.bat` 才会加载更新。选择值与上次游戏应用结果是两个状态：下拉框应保留 3 帧，但游戏应用结果仍需等目标计算函数下次执行。
