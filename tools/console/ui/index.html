启动前检查

            
    
            
    
            
    这些检查是什么
              
    每次启动前都会检查：游戏数据 data.arc 和它旁边的 .nrr 文件夹（缺了 .nrr，游戏会停在对战前的加载画面）、Media Foundation、Vulkan 驱动、包里的文件是否完整。红色项目会阻止启动，黄色只是提醒。
    
            
    
          
    
          
    
            
    游戏数据
    
            
            
            
    RomFS 文件夹放什么
              
    你自己的游戏备份里放 data.arc 的那个文件夹，整个复制过来，包括以点开头的隐藏文件夹 .nrr。相对路径以包的根文件夹为起点。改完按回车或点别处即保存。
    
            
    
            
    背景图
    
            
    
              
              
                
                
              
              
            
    
            
    放什么图
              
    开始页的背景，例如你自己那份游戏的封面。控制台不自带图片。图片会被调暗，复制到 config 文件夹的 cover 文件里，原文件可以删掉。支持 JPEG、PNG、WebP，最大 24 MB。
    
            
    
          
    
          
    
            
    运行记录
    
            
      
          
      
        
      
      
      
    
      

    
    
      
      
      画面
      改动立即保存，下一次启动游戏时生效。游戏里按 F11 可随时切换窗口和全屏。
      
      
      
        
      
          
      预设
      
          
      
            
            
          
      
          
      低配会改什么
            
      低配会覆盖三项：内部分辨率 0.5，各向异性过滤用游戏自己的值，垂直同步用程序时钟。实测 Intel 核显上每个战斗帧的显卡时间从 9.0 毫秒降到 4.2 毫秒。你在下面的设置仍然保留在文件里，切回自定义后恢复。
      
          
      
        
      

        
      
          
      渲染器
      
          
      
            
            
          
      
        
      

        
      
          
      窗口
      
          
      
            
            
            
          
      
          
      说明
            
      全屏不会切换显示器分辨率（独占全屏还没有实现）。画面始终保持 16:9，其他比例的窗口会出现黑边。
      
          
      
        
      

        
      
          
      垂直同步
      低配预设固定为程序时钟
      
          
      
            
            
            
            
            
            
          
      
          
      这几种有什么不同
            
      
              
      自动
      启动时测量刷新率。60、120、240 Hz 用“跟随显示器”，其他刷新率（75、144、165 Hz 等）用“程序时钟”。
      
              
      跟随显示器
      游戏的帧时钟就是显示器的刷新：每帧在屏幕上停留时间完全相同，不撕裂。刷新率不是 60 的倍数时自动退回“程序时钟”。
      
              
      程序时钟
      程序自己的 60 Hz 时钟。刷新率不是 60/120/240 的显示器上，偶尔有帧多停一次刷新，这无法避免。
      
              
      关闭
      画好就立即显示，允许撕裂，延迟最低。仍然是每秒 60 帧。
      
              
      Mailbox
      与程序时钟相同，但只用 mailbox 呈现模式。
      
              
      交换链 FIFO
      交换链自己的垂直同步加上程序时钟，两个时钟并存，不推荐。
      
            
      
            
      OpenGL 渲染器不读取这一项。
      
          
      
        
      

        
      
          
      输入延迟
      
          
      
            
            
            
          
      
          
      说明
            
      
              
      标准
      游戏在时钟节拍时开始一帧。
      
              
      低
      游戏在每帧较晚的时候才开始，刚好赶在下一节拍前画完，所以读手柄晚 2–5 毫秒，离显示更近。节奏不变；四人对战时慢帧可能稍多。
      
              
      最低
      在“低”的基础上，画好就立即送到窗口，不等节拍：再少约 4 毫秒，但每帧停留时间不再完全相同（会有轻微抖动）。
      
            
      
            
      仅 Vulkan。
      
          
      
        
      

        
      
          
      内部分辨率
      低配预设固定为 0.5
      
          
      
            
            
      
              
              
      
                
                
                
                
                
              
      
            
      
          
      
          
      说明
            
      1.0 是游戏原本的 1920×1080。低于 1.0 时整个画面（包括 2D 界面）按更小尺寸绘制再放大到窗口，是弱显卡最有效的开关，界面会变软。高于 1.0 是超采样，只适合强显卡：显卡时间和显存随倍数的平方增长。2.0 = 3840×2160。仅 Vulkan，OpenGL 忽略这一项。
      
          
      
        
      
      
      
      
      
    
      

    
    
      
      
      控制器
      
      
      
        
        
        
      
      

      
      
        
      
          
      
          
      
        
      
        
      
        
      
          
      
            
      
            
      
            
      点手柄上的按键，或者右边列表里的一行，就能修改它。
      
          
      
          
      
        
      
        
      映射怎么写
          
      每个 Pro 按键可以填一个或多个来源，用逗号分隔，任意一个按下都算。SDL 认识的手柄用名称：south（下）east（右）west（左）north（上）、leftshoulder、dpup、lefttrigger、leftx+ 等；任何设备都可以用编号：button3、axis2+、hat0up。“默认”= 这个设备本来的映射，“不映射”= 这个键不起作用。
      
          
      “无映射”的设备是 SDL 不认识的手柄，当作普通摇杆打开，按键顺序是猜的，用“逐键录入”一次设好全部按键最快。
      
        
      
      
      

      
      
        
      每个玩家用哪个设备。自动 = 手柄连接时占第一个空槽位，断开后重新连上会回到原来的槽位。
      
        
      
        
      固定设备有什么用
          
      指定设备后，这个槽位只留给它，即使它晚连接也一样。“无人”表示这个槽位不使用。
      
        
      
      
      

      
      
        
      
          
      
            
      面键布局
      
            
      
              
              
              
            
      
            
      说明
              
      
                
      按位置
      任天堂 A 键的位置（右）算 A：右 = A，下 = B，上 = X，左 = Y。Xbox 手柄的 B 键会当作 A。
      
                
      按标签
      按印的字母算：Xbox 手柄的 A 就是 Pro 手柄的 A。
      
                
      自动
      GameCube 手柄按标签，其他按位置。
      
              
      
            
      
          
      
          
      
            
      摇杆
      
            
      
              
      
              
      
                
                
              
      
            
      
            
      说明
              
      以满行程为 1。死区以内不算推动；超过外圈算推满；中间重新缩放，长度不超过 1（圆形边界）。默认 0.10 和 0.98。左边的圆是示意：内圈 = 死区，外圈 = 推满的位置。
      
            
      
          
      
          
      
            
      扳机
      
            
      
              
            
      
            
      说明
              
      扳机（或任何映射到按键的轴）推到这个位置（0–1）算按下 ZL / ZR。默认 0.33。
      
            
      
          
      
          
      
            
      震动
      
            
      
              
              
            
      
          
      
          
      
            
      不使用的设备
      
            
        
            
        
              
              
            
        
            
        什么时候用
              
        有些键盘接收器或外设会把自己伪装成摇杆，占掉一个玩家槽位。把它的 GUID 加进来，游戏就不会再使用它。更简单的办法：在“按键映射”里选中那个设备，点“不使用这个设备”。
        
            
        
          
        
        
        
      
        
      
        
    
        

    
    
        
      
        模组
        管理资源包。改动自动保存，下一次启动游戏时生效。
        
      
        
        检测中正在检查当前构建…
      
        
      
        
        
        
        
        
        
      
        
      
        
      
        游戏运行中，可以查看模组；关闭游戏后可修改。
        
      
        
      
        
        安装目录、槽位和兼容范围
        
        每个模组放在包根目录的 mods/模组名/ 下，与 game 文件夹同级。导入会识别压缩包内的 ultimate/mods 外层，并保留原文件。删除会移入 mods/.trash 回收区。
        
        
        内容标签由资源路径自动识别，包含替换和新增资源。槽位按“第 1 套 = c00”显示，只映射能够识别的服装及配套资源；公共资源保持公共。第 9 套起的额外槽位仍需要游戏对应的选择和运行支持。
        
        
        带 Switch 插件的包会单独标记，不能仅靠资源后端运行；这类包以及无法解析的哈希配置不支持自动改槽位。同路径覆盖提示表示多个启用包提供了相同文件。
        
      
        
      
        
    
        

    
    
        
      
        联机
        照常启动游戏，需要联机时在这里连接 Yuzu 房间服务器，再在游戏里选择“本地无线”。
        
      
          
        
        1. 1启动游戏
          2. 
        
        2. 2加入服务器房间
          3. 
        
        3. 3在游戏里选择本地无线
          4. 
      
        
      
        
        
        
          
        
            
            
          
        
          
          
        游戏内名字在开始页统一设置。
        
          
        两个名字的区别
            
        房间昵称给服务器看，原版服务器要求 4–20 个英文字母、数字、空格或 ._-，同一房间里不能重名。游戏内名字是 SSBU 里显示的名字，在开始页设置，可以用中文，最多 32 字节，对所有启动方式生效。
        
          
        
          
        
            
            
          
        
          
        密码会被保存吗
            
        不会。密码和 Token 只在加入房间时经管道交给游戏，不写进配置、会话记录或日志。地址、端口和昵称保存在 launcher.ini 里。
        
          
        
          
        
            
            
          
        
          
        不连接服务器也可以正常游玩。请在进入游戏的本地无线模式前完成连接。
        
          
        
        
        

        
        
          
        
            游戏未运行
            
        还没有加入房间
        
            
        
          
        
          
        
          
          
          
          加入房间后，成员显示在这里。
          
          
          断开后怎么重连
            
          先在游戏里退出本地无线会话，再离开房间、重新加入。控制台不会强行改游戏里的会话状态。服务器房间和游戏里的房间是两层：先进服务器房间，再在游戏里建房或加入。
          
          
          
        
          
      
          
    
          

    
    
          
      
          调试
          日志、dump 和测试用的启动选项。
          
      
          
        
          
          
          
            
            
            
            
            
          
          
          
          
          
          
            
            
            
            
          什么时候写 dump
              
          游戏卡住（画面不动、没有反应）而卡死检测没有报告时，先写 minidump 再结束游戏。dump 和这次运行的日志放在同一个会话文件夹里，报告 zip 会带上它。完整内存 dump 有几个 GB。
          
            
          
          
          
        
          

        
          
          
          
            
            
          
          

          
          
            
          只对从控制台启动的下一次运行生效，不保存。
          
            
          
              
              
            
          
            
          速度倍数
              
          刷新时钟加快 n 倍，0 = 不限速。游戏逻辑不跳帧，但声音会错乱，配合“静音”使用。只用于测试。
          
            
          
            
          
              
              
              
            
          
            
            
          接口审计
              
          游戏调用系统接口时，检查它是真正实现的、提升的还是简化的。“遇到未实现就停止”会在游戏第一次调用未真正实现的接口时停下，日志里写明是哪个。
          
            
          

            
          指定对战
          
            
          
              
              
            
          
            
          
              
              
            
          
            
          
              
              
              
            
          
            
            
          指定对战怎么用
              
          填了角色或舞台后，游戏照常走菜单，但在确认对战时把设置替换成这里的。角色用内部名（mario、donkey、kirby、captain、ganon…），舞台用 ui_stage 名（battle_field、end、mario_castle64…，也接受 battlefield、fd）。需要用测试输入序列自动走菜单，或手动选一场对战。道具和场地机关项未验证，这里没有提供。
          
            
          
            
          
          
          

          
          
            
          写进 launcher.ini，每次启动都生效。改动立即保存。
          
            
          
              
              
            
          
            
          随机数种子
              
          auto = 每次随机选一个并记下来，回放时用同一个；none = 不固定；或者填一个数字。
          
            
          
            
          
              
              
            
          
            
          这两项是什么
              
          确定性模式：战斗开始时固定脚本随机数，机器慢时不补逻辑帧，回放更容易一致；关闭后行为和正常游戏完全相同。状态散列：每个战斗帧记录角色状态，回放时能找出第一处不同的帧。
          
            
          
            
          
              
              
            
          
            
          
              
              
            
          
            
          排除逻辑处理器
              
          不让游戏在这些逻辑处理器上运行，用于排查个别核心不稳定导致的崩溃。编号从 0 开始，逗号分隔。
          
            
          
            
          额外的环境变量
          
            
          
            
            
          说明
              
          每次启动都传给游戏，例如 SSBU_RENDERER = gl。完整列表在 BUILDING.md 和运行时源码开头。“下次启动”里的选项与这里冲突时，以“下次启动”为准。
